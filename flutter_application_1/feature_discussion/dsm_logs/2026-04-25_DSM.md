# DSM Log: 2026-04-25 - Project Audit & "Council of Agents" Kickoff

**Goal:** Conduct a comprehensive audit of the SpendSense project to identify critical shortcomings across all specialized domains.

---

## 📋 PM Agent (Product Manager)
**Status:** 🚩 AT RISK
**Shortcomings:**
- **Incomplete Domain Coverage:** We are currently an "Expense" tracker, not an "Income" or "Refund" tracker. This makes our ledger incomplete for a true financial overview.
- **Weak Deduplication:** Our deduplication logic is currently body-hash based and exists only on the client. We lack cloud-side idempotency.
- **Limited Bank Support:** The local parser only supports 4 banks. We need a more scalable strategy for the 100+ UPI-enabled banks in India.

## 💻 Flutter Agent (Lead Developer)
**Status:** 🏗️ TECHNICAL DEBT ALERT
**Shortcomings:**
- **God Object Pattern:** `AppState.dart` is bloated (orchestration + parsing + sync + UI state). It needs to be refactored into domain-specific services.
- **Blocking Sync:** Confirmation and sync are sequential. Confirming 10 transactions in a daily digest blocks the UI for 5-10 seconds.
- **State Inconsistency:** We are mixing `SharedPreferences` and `SecureStorage` for configuration, leading to migration risks.

## 🧪 QA / SDET Agent (Test Automation)
**Status:** 📉 LOW COVERAGE
**Shortcomings:**
- **Zero E2E/UI Tests:** We have unit tests for models, but no automated validation that an SMS actually results in a transaction appearing on the Home Screen.
- **Brittle Parsing:** Our regex-based parsing is a "black box" that isn't being tested against a wide corpus of actual bank SMS variations.
- **Regression Risk:** No automated regression suite to ensure new logic doesn't break established SMS triggers.

## 🎨 UX/UI Agent (Designer)
**Status:** 💅 LACKS POLISH
**Shortcomings:**
- **Notification Overwrites:** We use a single ID for all transaction popups. If two transactions happen back-to-back, the second one "eats" the first.
- **Invisible Sync:** There is no "Syncing..." spinner or health status. Users don't know if their data is actually in Google Sheets until they check the sheet.
- **Confirmation Fatigue:** The daily digest UI is purely functional and lacks the "vibe" of a modern financial app.

## 🔒 SecOps Agent (Cybersecurity)
**Status:** 🛠️ IN PROGRESS (SPEND-005)
**Shortcomings:**
- **Plaintext Ledger:** The SQLite database is not encrypted. Any app with root or backup access could read the user's entire financial history. (Current Focus)
- **Unauthenticated Backend:** The Google Apps Script webhook is open to "Anyone." There is no shared secret or API key check to prevent malicious data injection.
- **Foreground Leak:** Background SMS processing logs may contain PII in the console (unmasked amounts/sender IDs).

**Update [17:02]:** Starting implementation of `sqflite_sqlcipher`. Collaborating with FlutterDev to migrate `LocalStorageService`.

## ⚙️ DevOps Agent (Infrastructure)
**Status:** 🧱 MANUAL PROCESSES
**Shortcomings:**
- **No CI/CD:** We are building APKs and running tests manually. No GitHub Actions to catch PR regressions.
- **Non-Idempotent Sync:** If a sync fails midway, retrying results in duplicate rows in Google Sheets.
- **No Crash Reporting:** We have no Sentry or Firebase Crashlytics. We are blind to production crashes.
